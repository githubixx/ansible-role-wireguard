## Включение

```yaml
# group_vars/vpn.yml
wireguard_preshared_keys: true
```

После этого PSK будет у каждого туннеля:

- **между хостами под управлением роли**: один PSK на пару, в
  `state/psk/<host-a>--<host-b>.psk`. Если PSK включён хотя бы у одного
  хоста пары, он прописывается обоим;
- **у каждого клиента из `wireguard_clients`**: в
  `state/clients/<сервер>/<клиент>.psk`. Для отдельного клиента PSK можно
  отключить через `use_preshared_key: false`.

PSK — это 32 случайных байта из `secrets.token_bytes` в base64, тот же
формат, что у `wg genpsk`.

## Зачем это нужно

Handshake WireGuard построен на Curve25519. Достаточно мощный квантовый
компьютер сможет его взломать, причём и для трафика, записанного сегодня
(«harvest now, decrypt later»). PSK подмешивается в вывод ключей как
дополнительный симметричный секрет. Пока PSK не утёк, записанный трафик
не расшифровать даже со взломанным Curve25519.

Защита работает, только если PSK передавался по защищённому каналу. Здесь
это SSH (для хостов) и ваш способ доставки конфигов на устройства (для
клиентов).

## Существующая сеть

Если включить `wireguard_preshared_keys` в уже работающей сети, при
следующем запуске PSK добавятся в конфиги всех хостов. Хосты переживут
это без ручных действий. Клиентам нужно заново импортировать конфиг.

## PSK для `wireguard_unmanaged_peers`

Для пиров из `wireguard_unmanaged_peers` PSK задаётся вручную полем
`preshared_key`, как в upstream.
