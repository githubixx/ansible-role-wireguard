---
title: Клиенты без SSH
description: Генерация и локальное сохранение конфигов для телефонов, ноутбуков и ПК, которыми Ansible не управляет.
---

Телефоны, ноутбуки и ПК без SSH описываются в `wireguard_clients` на хосте,
к которому они подключаются (обычно это VPN-сервер). Для каждого клиента
роль:

1. один раз генерирует приватный ключ и, если нужно, PSK на контроллере;
2. добавляет клиента пиром в конфиг сервера;
3. пишет готовый конфиг в
   `<wireguard_local_directory>/clients/<сервер>/<клиент>.conf`;
4. при `wireguard_clients_qrcode: true` рядом кладёт `<клиент>.png`.

Приватный ключ клиента не попадает на сервер. На сервер передаётся только
публичный ключ, полученный через `wg pubkey` / `awg pubkey`.

## Пример

```yaml
# host_vars/vpn1.yml
wireguard_clients_defaults:
  allowed_ips: ["10.8.0.0/24", "192.168.10.0/24"]
  dns: "192.168.10.1"
  persistent_keepalive: 25

wireguard_clients:
  phone:
    address: "10.8.0.10/32"
  laptop:
    addresses: ["10.8.0.11/32", "fd00:8::11/128"]
    allowed_ips: ["0.0.0.0/0", "::/0"]   # весь трафик через VPN
  office-router:
    address: "10.8.0.20/32"
    networks: ["192.168.50.0/24"]        # сеть за клиентом
  old-tablet:
    state: absent                        # удалить
```

## Поля клиента

| Поле | Обязательно | По умолчанию | Описание |
|---|---|---|---|
| `address` / `addresses` | да | — | адрес(а) клиента в туннеле |
| `allowed_ips` | нет | сети из `wireguard_address(es)` сервера | что клиент направляет в туннель (см. [Маршрутизация](../routing/)) |
| `dns` | нет | — | строка или список DNS-серверов |
| `mtu` | нет | — | MTU интерфейса клиента |
| `persistent_keepalive` | нет | — | секунды; нужно за NAT |
| `endpoint` | нет | `wireguard_endpoint` сервера, иначе `inventory_hostname` | адрес сервера для клиента |
| `port` | нет | `wireguard_port` | порт сервера |
| `networks` | нет | `[]` | сети за клиентом, сервер маршрутизирует их к клиенту |
| `use_preshared_key` | нет | `wireguard_preshared_keys` | PSK для этого клиента |
| `amneziawg_params` | нет | `{}` | свои `jc`/`jmin`/`jmax` |
| `state` | нет | `present` | `absent` удаляет пир и локальные файлы |

`wireguard_clients_defaults` накладывается под каждого клиента. Поле,
заданное у клиента, побеждает значение из defaults.

## Где хранятся файлы

```text
wireguard-artifacts/                       # wireguard_local_directory
├── clients/<сервер>/<клиент>.conf         # раздавать на устройства
├── clients/<сервер>/<клиент>.png          # QR (опционально)
└── state/clients/<сервер>/<клиент>.key    # приватный ключ — не удалять
    state/clients/<сервер>/<клиент>.psk
```

Каталог по умолчанию — `{{ playbook_dir }}/wireguard-artifacts`. В нём
секреты, поэтому:

- не коммитьте его в открытом виде. Добавьте в `.gitignore` или шифруйте
  через git-crypt, SOPS или age;
- не теряйте `state/`. Без него при следующем запуске клиенты получат
  новые ключи, и устройства придётся перенастраивать.

## Клиент нескольких серверов

Опишите клиента у каждого сервера. Для каждого сервера будет отдельный
конфиг (`clients/vpn1/laptop.conf`, `clients/vpn2/laptop.conf`) со своими
ключами.

## Чем отличается от `wireguard_unmanaged_peers`

`wireguard_unmanaged_peers` из upstream только добавляет на сервер пир с
уже известным публичным ключом. Ключи и конфиг для устройства вы делаете
сами. `wireguard_clients` делает всё это за вас. Обе переменные можно
использовать одновременно.
