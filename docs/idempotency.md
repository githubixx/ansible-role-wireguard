---
title: Идемпотентность
description: Какие ключи и где сохраняются, чтобы повторный запуск плейбука ничего не перегенерировал.
---

Повторный запуск плейбука без изменений в переменных даёт `changed=0`.
Ключи не перегенерируются.

## Откуда берутся ключи при повторном запуске

| Секрет | Где хранится | Как переиспользуется |
|---|---|---|
| Приватный ключ хоста под управлением Ansible | в его конфиге на самом хосте | при запуске роль читает `PrivateKey` из существующего конфига |
| Приватный ключ клиента без SSH | `state/clients/<сервер>/<клиент>.key` на контроллере | файл создаётся, только если его нет |
| PSK между хостами | `state/psk/<host-a>--<host-b>.psk` | то же |
| PSK клиента | `state/clients/<сервер>/<клиент>.psk` | то же |
| Параметры AmneziaWG | `state/amneziawg-params.json` | то же |

Файлы на контроллере создаёт `files/wg_keystore.py`. Он открывает файл с
флагом `O_EXCL`, так что существующий файл перезаписать невозможно. Права:
`0600` на файлы и `0700` на каталоги.

Общие секреты (PSK пар хостов, параметры AmneziaWG) генерируются с
`run_once`. Поэтому два хоста не могут одновременно создать один и тот же
файл с разным содержимым.

## Как зафиксировать ключ хоста явно

Если хост пересоздаётся (новая VM), ключ из старого конфига теряется.
Чтобы этого избежать, задайте ключ сами и зашифруйте его через Ansible
Vault:

```yaml
wireguard_private_key: !vault |
  $ANSIBLE_VAULT;1.1;AES256
  ...
```

## Как намеренно сменить ключи

- Клиент: удалите `state/clients/<сервер>/<клиент>.key` (и `.psk`) и
  запустите плейбук.
- PSK пары хостов: удалите соответствующий файл в `state/psk/`.
- Хост: удалите его конфиг на хосте или поменяйте `wireguard_private_key`.
